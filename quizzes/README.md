# 理解度テストの制作計画

更新2026-11-14。本文・問題・解答の完成版はPhase 5で章単位に制作する。

各章に用語確認、条件判断、操作結果の解釈、障害診断、発展設計を設ける。単純暗記だけにせず「なぜその設定か」「採用しない条件は何か」を問う。

| 種類 | 形式 | 採点の根拠 |
|---|---|---|
| 基本理解 | 概念の比較、短答 | 定義・関係・責務が正しい |
| 利用条件 | plan/role/visibility付き選択問題 | 条件を満たすか出典で判断する |
| 履歴と実行 | diff・ログ・workflow読解 | ref・SHA・token・checkを説明できる |
| 障害対応 | 症状から追加観察と解決を提案 | 原因を断定せず証拠を選べる |
| 設計 | 小規模/大規模/AIの構成課題 | 要件・選択理由・制約・代替・監査が揃う |

問題ID、対応章/Feature IDs、学習目標、前提、出題、正解、理由、誤答が誤りである理由、出典、確認日を保存する。Preview/料金の変化で答えが変わる問題は確認日を明示する。

章レビューでは問題が本文を写しただけになっていないか、複数解がある設計を唯一解にしていないかを確認する。実行できない有料機能は仕様判断の問題とし、操作再現を達成したと採点しない。
