# 企業公開事例の調査計画

更新2026-11-14。Phase 3の計画であり、下記企業の現在の運用を検証した事例集ではない。

| 候補 | 調査する課題 | 優先情報源 | 採用条件 |
|---|---|---|---|
| Shopify | 大規模PR・CI・開発体験 | 当事者技術ブログ、GitHub公式事例 | 具体的な機能・ワークフローと公開成果が確認できる |
| メルカリ | チーム横断統制、Actions、権限 | 公式Engineering Blog | 対象時期と構成、課題、判断理由が記載される |
| Duolingo | AI支援・レビュー・開発効率 | 当事者発表、Customer Stories | 数値の定義・測定期間と製品境界を確認できる |
| Spotify | 開発基盤・標準化 | 当事者Engineering Blog | GitHub機能と社内システムの責務が分かれる |
| GitHub Engineering | GitHub自身の開発・運用 | Engineering Blog、公式OSS | 公開時点の実装と一般化できる条件が明確 |

最初はPRレビュー運用1件とCI/CD1件を選ぶ。企業名から成功を決めず、一次資料が具体的課題と成果を支持する事例を採用する。根拠不足なら候補のまま残す。

## 記録テンプレート

- 事例ID、企業、対象チーム、記事タイトル/URL、公開日、確認日。
- 当事者が述べた課題、利用機能、構成、採用理由、成果。
- 成果の測定対象・期間・比較条件・自己申告か独立検証か。
- 各主張を支持する出典の位置と要約。非公開の運用は補完しない。
- 事例の制約、当時と現行仕様の差、未確認事項。
- 著者による一般化した設計、適用できる条件、小規模化したとき省く構成。
- 関連Feature IDs、章、Lab、追加調査・レビュー担当。

実際の企業の事実、公開記事からの推論、教材の推奨設計を見出しで分ける。古い事例を現在の運用と説明しない。公開コードを使う場合はlicenseと再現可能範囲を確認する。
